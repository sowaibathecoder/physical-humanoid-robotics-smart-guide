## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/your-username/physical-humanoid-robotics-smart-guide.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Test your changes
6. Commit and push
7. Submit a pull request

## Development Workflow

### Setting up the environment
```bash
# Install dependencies
npm install

# Start the development server
npm start
```

### Project Structure
- `docs/` - Course content organized by modules and weeks
- `src/labs/` - Weekly lab templates organized by module
- `static/` - Static assets (images, diagrams, videos)
- `src/` - Docusaurus customization
- `specs/` - Specification and planning documents

## Content Guidelines

### Writing Style
- Write in clear, accessible English
- Use active voice when possible
- Keep sentences concise and to the point
- Follow IEEE citation style for references

### Technical Accuracy
- Ensure all code examples are tested and functional
- Verify that all information is technically accurate
- Include relevant citations from peer-reviewed sources (70%+ of 120+ citations should be from categories 1-3 as per constitution)

### Accessibility
- Use proper heading hierarchy (H1, H2, H3, etc.)
- Include alternative text for images
- Ensure sufficient color contrast
- Write descriptive link text

## Code Style

### Markdown
- Use consistent heading levels
- Follow the existing document structure
- Use proper code block syntax with language specification

### JavaScript/TypeScript
- Follow the ESLint configuration provided in the project
- Use descriptive variable and function names
- Include JSDoc comments for complex functions

### Python
- Follow PEP 8 style guide
- Use meaningful variable names
- Include docstrings for functions and classes

## Submitting Changes

1. Ensure your changes are well-tested
2. Update documentation as needed
3. Add or update tests if applicable
4. Run linting and fix any issues
5. Commit changes with clear, descriptive messages
6. Push to your fork
7. Create a pull request with a clear description

### Pull Request Guidelines
- Keep pull requests focused on a single feature or fix
- Include a clear description of the changes
- Reference any related issues
- Ensure all tests pass
- Update documentation as needed

## Community Guidelines

### Code of Conduct
- Be respectful and inclusive
- Provide constructive feedback
- Help others learn
- Follow the project's code of conduct

### Review Process
- All contributions will be reviewed by maintainers
- Feedback will be provided to help improve the contribution
- Changes may be requested before merging
- Contributions that don't meet quality standards may be rejected

## Questions?

If you have questions about contributing, feel free to open an issue or contact the maintainers.

Thank you for contributing to the Physical AI & Humanoid Robotics course!
